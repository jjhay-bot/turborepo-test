One Git repository, two live websites

We deploy the Admin and School Portal independently, even though they share one Turborepo repository. Supabase stays as the single backend.

Before deployment

Set up the repository once

1

Create the workspace

Run this in the folder where you want the new repository. The setup is interactive, so choose pnpm and Turborepo.

pnpm dlx create-turbo@latest <repository-name>
cd <repository-name>
2

Create the two apps

We will guide this after the workspace exists: apps/admin for library staff and apps/school-portal for the public website.

3

Connect Supabase

After creating the Supabase project, link the repository and preview schema changes before applying them.

pnpm dlx supabase login
pnpm dlx supabase link --project-ref <your-project-ref>
pnpm dlx supabase db push --dry-run
pnpm dlx supabase db push
Do not run the last command until migrations exist and you have reviewed the dry run. It changes the remote database schema.

Vercel deployment

Create two projects from the same repository

1

Push the repository to GitHub

Vercel watches this repository. Every future push can create preview deployments automatically.

2

Import Admin in Vercel

In Vercel: Add New → Project, select the repository, then set its Root Directory to apps/admin. Name the Vercel project library-admin.

3

Import School Portal in Vercel

Repeat the import with the same repository, but set Root Directory to apps/school-portal. Name it school-portal.

4

Add environment variables to both projects

Add the correct public Supabase URL and publishable key in each Vercel project’s Settings → Environment Variables. Never add the service-role key to browser-exposed variables.

Domains

Point each subdomain to its own Vercel project

Library Admin

admin.yourdomain.com
→ Vercel project: library-admin

School Portal

school.yourdomain.com
→ Vercel project: school-portal

Future User UI

app.yourdomain.com
→ a future Vercel project

In each Vercel project, open Settings → Domains, add the subdomain, then follow the exact DNS record Vercel shows. Do not guess the record; the required CNAME can vary by configuration.

Production checklist

Ready when these are true

  • Both apps are separate Vercel projects using the correct root directory.
  • Each Vercel project has its required Supabase environment variables.
  • Supabase tables have Row Level Security policies.
  • Only reviewed migrations were pushed to the remote database.
  • admin and school subdomains resolve and show HTTPS.
  • Admin routes require the intended staff authorization.
Important mental model: one repository does not mean one deployment. Each app directory becomes its own Vercel project, URL, environment variables, and deployment lifecycle.
